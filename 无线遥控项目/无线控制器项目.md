项目介绍
为了辅助我进行我一个的关于嵌入式领域的新项目的推进,关于该项目我的组长给我一个项目是,主机是使用GD32E230C8T6作为主控芯片以及自带的芯片和天线发送数据,随后从机使用D32E230C8T6作为主控芯片的同时使用CMT2219B作为接收数据时使用的芯片

## 相关函数使用方法
### 串口配置参数命令使用方法
如下
```text
SET,TX,40,16,100
```

配置发送芯片。

```text
SET,RX,40,16,100
```

配置接收芯片。

```text
SET,BOTH,40,16,100
```

同时配置发送和接收芯片。

参数含义：

```text
40   -> fh_offset
16   -> fh_channel
100  -> channel_count
```

处理成功返回：

```text
OK
```

处理失败返回：

```text
ERROR
```
### 串口打印收发芯片的真实寄存器配置
```
/* 读取并打印收发芯片当前真实寄存器配置 */
rf_print_tx_rx_real_freq();
```


## 项目可能排查故障
### 211初始化相关
```c
radio_tx_init();
```
211发送代码,不会检查故障:
目前只是形式上判断，实际上正常运行到 `return CMT2119B_OK;` 就一定会打印：

```text
TX init OK
```
也就是说：  
**现在这份代码还没有真正检测发送芯片是否初始化失败。**

比如这些情况：

- 发送芯片没接好
- SPI 引脚接错
- 寄存器没写进去
- 芯片没有响应
因为里面这些函数：

```c
cmt2119b_spi_init();
cmt2119b_soft_reset();
cmt2119b_config_reg_bank(...);
cmt2119b_write_reg(...);
```

都是只执行操作，没有返回失败结果。
