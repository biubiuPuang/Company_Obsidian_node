## HPM各种函数的意思
![[Pasted image 20260627154815.png]]
这种相当于STM32的库函数或者说是LL函数

SDK_drivers下不同文件的意思
![[Pasted image 20260629140312.png]]

![[Pasted image 20260629140320.png]]


其中boards.c是官方开发板才配套的函数
drivers.c是类比与stm32的官方库函数
日常交流中也可以直接说 **"用 driver 那套"** 和 **"用 component 那套"**，行业内做 HPM 开发的人都能听懂。
hpm和stm两者之间的差异
关键差异：HPM 的 components 是 drivers 的**薄封装**，不是替代
这和 STM32 不同——ST 的 HAL 和 LL 是两套独立代码，互不依赖。而 HPM 的 `components` 是 **在 `drivers` 之上叠一层**，你甚至可以混用
// 用 components 的简便 API 做初始化
hpm_i2c_initialize(&ctx);

// 特殊情况用 drivers 的底层函数手动干预
i2c_master_issue_data_transmission(I2C0);  // drivers 级别


| 开发方式                 | HPM 官方名称                    | 对应 STM32                          |
| -------------------- | --------------------------- | --------------------------------- |
| 用 `drivers/` 下的函数    | **驱动层开发** (Driver-layer)    | ≈ STM32 的 **LL库开发** / **标准外设库开发** |
| 用 `components/` 下的函数 | **组件层开发** (Component-layer) | ≈ STM32 的 **HAL库开发**              |

## 工程文件_BSP函数及官方外设驱动函数的使用
### 1:提问
那要是我想使用板级SBP封装函数,但是就是说这些函数原本他就不是我写的嘛,那我如何去查看有哪些函数以及看懂这些函数是怎么使用的呢,以及这些函数使用的是哪些引脚这些个问题
### 1:回答
这个问题问到关键了：BSP 不是不能用，真正的问题是你要学会“顺藤摸瓜”看它到底封装了什么。下面我按你现在的 HPM5300EVK 场景讲。

已思考 12s

你说的 **SBP** 应该是 **BSP**，全称是：

**Board Support Package，板级支持包。**

它的核心意思是：

> 官方提前帮某一块开发板写好的初始化函数、引脚宏、外设默认配置。

比如 HPM5300EVK 里面的：

```
board_init();board_init_gpio_pins();board_delay_ms();BOARD_LED_GPIO_CTRL;BOARD_LED_GPIO_PIN;BOARD_CONSOLE_UART_BASE;
```

这些就是 BSP 相关内容。

---

你怎么查看有哪些 BSP 函数？

最直接看这几个文件：

```
hpm_sdk/ └── boards/     └── hpm5300evk/         ├── board.h         ├── board.c         ├── pinmux.c         ├── clock_config.c         └── 其他配置文件
```

你重点先看：

```
board.hboard.cpinmux.c
```

它们的作用大概是：

|文件|主要看什么|
|---|---|
|`board.h`|有哪些 BSP 函数、有哪些板级宏|
|`board.c`|这些 BSP 函数内部到底做了什么|
|`pinmux.c`|这块板子把哪些芯片引脚配置成 UART/GPIO/SPI 等功能|
|`clock_config.c`|系统时钟、外设时钟怎么配置|

---

最重要的入口：先看 `board.h`

`board.h` 一般相当于 BSP 的“说明书”。

你打开它之后，主要找两类东西。

第一类是函数声明：

```
void board_init(void);void board_init_gpio_pins(void);void board_delay_ms(uint32_t ms);
```

这表示你可以在 `main.c` 里面调用这些函数。

第二类是板级宏定义：

```
#define BOARD_LED_GPIO_CTRL#define BOARD_LED_GPIO_INDEX#define BOARD_LED_GPIO_PIN#define BOARD_CONSOLE_UART_BASE#define BOARD_CONSOLE_UART_IRQ#define BOARD_CONSOLE_UART_BAUDRATE
```

这些宏表示：

> 官方已经帮你定义好了开发板上某个外设对应的芯片资源。

比如：

```
BOARD_LED_GPIO_PIN
```

可能表示开发板 LED 接到了哪个 GPIO 引脚。

比如：

```
BOARD_CONSOLE_UART_BASE
```

可能表示开发板默认调试串口使用的是哪个 UART 外设。

---

怎么看懂 BSP 函数内部做了什么？

比如你代码里看到：

```
board_init();
```

你不要只看它名字，你要在 VSCode 里面：

**按住 Ctrl，然后鼠标左键点 `board_init`**

它会跳转到 `board.c` 里面，通常你会看到类似这种结构：

```
void board_init(void){    board_init_clock();    board_init_console();    board_init_gpio_pins();}
```

这就说明：

```
board_init();
```

不是一个神秘函数，它只是官方把很多初始化步骤打包到一起了。

继续顺着点进去：

```
board_init_console();
```

你可能会看到它配置了串口。

```
board_init_gpio_pins();
```

你可能会看到它配置了 LED、按键或者其他 GPIO。

所以看 BSP 的方法就是：

```
main.c 里面看到 board_xxx()        ↓Ctrl + 左键跳进去        ↓看 board.c 里面调用了哪些更底层函数        ↓继续跳到 gpio_xxx / uart_xxx / clock_xxx / ioc_xxx        ↓最后你就知道它到底配置了什么
```

---

怎么知道 BSP 函数使用了哪些引脚？

看三个地方，按重要程度排序：

第一，看 `board.h` 里的宏

比如你看到：

```
#define BOARD_LED_GPIO_CTRL   GPIO0#define BOARD_LED_GPIO_INDEX  GPIO_DO_GPIOA#define BOARD_LED_GPIO_PIN    23
```

那意思大概就是：

> 开发板 LED 接在 GPIO0 控制器的某个 GPIO 组，第 23 号引脚。

再比如：

```
#define BOARD_CONSOLE_UART_BASE HPM_UART0
```

说明默认控制台串口用的是：

```
UART0
```

---

第二，看 `pinmux.c`

这个文件非常重要。

因为芯片的一个物理引脚通常可以复用成不同功能，比如：

```
普通 GPIOUART TXUART RXSPI CLKI2C SDAPWM 输出
```

所以光知道用哪个 UART 还不够，还要知道：

```
哪个物理引脚被配置成 UART_TX？哪个物理引脚被配置成 UART_RX？
```

这一般就在 `pinmux.c` 里面。

你可能会看到类似这种代码：

```
init_uart_pins();init_gpio_pins();
```

或者：

```
HPM_IOC->PAD[某个引脚].FUNC_CTL = IOC_PAD_FUNC_CTL_ALT_SELECT_SET(...);
```

它的作用就是配置引脚复用。

你要重点找这些关键词：

```
uartconsoletxrxgpioledpinmuxioc
```

---

第三，对照原理图

最终最可靠的是原理图。

因为 SDK 里面写的是软件配置，原理图告诉你硬件实际连线。

比如你想知道 J8 Type-C 串口到底接到 HPM5361 哪两个引脚，你就要从原理图里面看：

```
J8 Type-C   ↓USB 转串口芯片 / 调试芯片   ↓HPM5361 的 UART_TX / UART_RX 引脚
```

然后再回到 SDK 里面看：

```
board.h 里面默认 console UART 是哪个 UARTpinmux.c 里面 UART TX/RX 配置到了哪些引脚
```

三者对应上，就说明你找对了。

---

举个最实际的例子：看 LED 用了哪个引脚

假设代码里有：

```
gpio_toggle_pin(BOARD_LED_GPIO_CTRL,                BOARD_LED_GPIO_INDEX,                BOARD_LED_GPIO_PIN);
```

你想知道 LED 是哪个引脚，就不要猜，直接跳到 `BOARD_LED_GPIO_PIN` 的定义。

在 VSCode 里：

```
Ctrl + 鼠标左键点 BOARD_LED_GPIO_PIN
```

或者全局搜索：

```
BOARD_LED_GPIO_PIN
```

然后你会找到类似：

```
#define BOARD_LED_GPIO_CTRL   GPIO0#define BOARD_LED_GPIO_INDEX  GPIO_DO_GPIOA#define BOARD_LED_GPIO_PIN    23
```

那么你就知道：

```
LED 的控制引脚被 BSP 定义在这里。
```

然后你再去原理图里查这个 GPIO 对应 HPM5361 的哪个物理管脚。

---

举个串口例子：看 J8 Type-C 用哪个串口

你应该搜这些关键词：

```
BOARD_CONSOLE_UART_BASEBOARD_CONSOLE_UART_TXBOARD_CONSOLE_UART_RXconsoleuartinit_uart_pins
```

如果你看到：

```
#define BOARD_CONSOLE_UART_BASE HPM_UART0
```

那么说明默认 printf 串口是：

```
UART0
```

然后你继续去 `pinmux.c` 里找 UART0 的 TX/RX 引脚配置。

如果 `pinmux.c` 里有类似：

```
init_uart_pins(BOARD_CONSOLE_UART_BASE);
```

或者：

```
ioc_set_pin_mux(... UART0_TX ...);ioc_set_pin_mux(... UART0_RX ...);
```

那你就能知道：

```
UART0_TX 对应哪个芯片引脚UART0_RX 对应哪个芯片引脚
```

最后再对照原理图确认它是不是连到了 J8 Type-C 相关电路。

---

怎么看这些函数应该怎么用？

有三个办法。

第一，看官方例程怎么调用

比如你想知道 GPIO 怎么用，就搜索官方例程：

```
gpioledbutton
```

想知道 UART 怎么用，就搜索：

```
uartconsoleprintf
```

你看例程里面 `main.c` 怎么写，就能知道官方推荐的调用顺序。

---

第二，看函数声明和注释

比如打开：

```
hpm_gpio_drv.h
```

你会看到函数声明：

```
void gpio_set_pin_output(...);void gpio_write_pin(...);void gpio_toggle_pin(...);
```

一般上面会有注释，告诉你参数是什么意思。

---

第三，看 BSP 怎么调用底层驱动

这是最适合你的方法。

比如你想学 GPIO，就看：

```
board_init_gpio_pins();
```

它里面如果调用了：

```
gpio_set_pin_output();gpio_write_pin();
```

那你就知道官方配置 GPIO 的标准写法。

也就是说：

> BSP 本身就是一份“官方示范答案”。

你可以先用它，后面再拆开它。

---

你现在应该形成一个固定查看流程

以后你拿到任何官方 BSP，都按这个顺序看：

```
1. 找 boards/开发板名/board.h   ↓2. 看里面有哪些 BOARD_xxx 宏和 board_xxx 函数   ↓3. 打开 board.c   ↓4. 看 board_init() 内部到底调用了什么   ↓5. 打开 pinmux.c   ↓6. 看 UART/GPIO/SPI/I2C 等外设被复用到了哪些引脚   ↓7. 对照原理图确认这些引脚接到了什么硬件
```

这个流程比你直接啃芯片手册快很多。

---

你不用害怕 BSP 不是你写的

BSP 函数虽然不是你写的，但它不是黑盒。

因为它的源码就在 SDK 里面。

你可以把它理解成：

```
官方帮你写好的参考代码
```

你可以：

```
直接调用它复制它的一部分出来改顺着它学习底层驱动怎么用把它改成适合自己板子的 BSP
```

工业开发里非常常见。

---

对你现在最实用的结论

你现在如果想使用 BSP，就重点掌握这几个文件：

```
board.h       看有哪些函数和宏board.c       看 BSP 函数内部做了什么pinmux.c      看引脚复用配置clock_config.c 看时钟配置原理图        确认硬件实际连接
```

你记住一句话就够了：

> `board.h` 看“能用什么”，`board.c` 看“怎么实现”，`pinmux.c` 看“用了哪些引脚”，原理图看“这些引脚实际接到哪里”。

对于你现在的 HPM5300EVK 来说，下一步最建议你做的是：打开 `hpm_sdk/boards/hpm5300evk/board.h`，全局搜索 `BOARD_CONSOLE_UART_BASE`，你就能开始追 J8 Type-C 串口到底用的是哪个 UART。
